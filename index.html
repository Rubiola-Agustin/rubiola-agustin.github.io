01

NutriAppProyecto principal

Problema
Los nutricionistas llevan agenda, fichas clínicas y seguimiento repartidos entre planillas, WhatsApp y papel. Además, saber qué come el paciente depende de que lo anote a mano.
Solución
Plataforma web multi-inquilino para nutricionistas y sus pacientes: agenda, fichas clínicas, seguimiento de bioimpedancia y análisis de comidas por foto con IA. Cada profesional trabaja con sus datos aislados del resto.

Detalle técnico

  • Multi-tenant con RLS en Postgres: el aislamiento entre profesionales se resuelve en la base de datos, no en el frontend.
  • Claude API (Sonnet 4.6) invocada desde Edge Functions en Deno, sin SDK: la API key nunca llega al navegador.
  • pg_cron para recordatorios automáticos de turnos, con control para no duplicar envíos.
  • Realtime para notificaciones dentro de la app y Web Push para avisos en el celular, probado en Android e iOS.
  • Supabase Auth y Storage; paneles separados para nutricionista y paciente.

IA aplicada · cómo funciona

Fotos de comidas
  1. La foto se comprime en el cliente antes de subirla.
  2. Claude devuelve en JSON los alimentos detectados, calorías aproximadas, proteínas, carbohidratos y grasas, más una devolución de 2 o 3 oraciones.
  3. La respuesta se valida a mano: forma, tipo de cada campo y números finitos. Las claves de más se descartan.
  4. Si la respuesta es inválida o la API falla, la comida queda guardada sin análisis.
  5. El servidor limita los intentos por comida y las comidas analizadas por día.
Estudios de bioimpedancia
  1. La nutricionista sube una foto o un PDF del informe del equipo.
  2. La IA extrae 23 valores numéricos, más fecha y sexo.
  3. Una segunda llamada genera dos resúmenes: uno técnico para la nutricionista y otro motivador para el paciente.
  4. La nutricionista revisa y edita todo en un formulario. Nada se guarda hasta que confirma, y el paciente solo ve mediciones confirmadas.

En la interfaz, el análisis automático tiene un color propio y el rótulo «Análisis automático (apoyo, no reemplaza tu criterio)», para distinguirlo de lo que carga la profesional.

Inventario Lab v2

Inventario de insumos e instrumentos de laboratorio · en uso en una escuela técnica

Problema
La primera versión (Node, Express y MySQL) funcionaba, pero al relevar su seguridad encontré:
  • una API sin autenticación: cualquiera con la URL podía borrar usuarios o insumos;
  • contraseñas en texto plano, devueltas en la respuesta al crear usuarios;
  • credenciales de la base expuestas en los logs;
  • XSS almacenado por insertar datos de la base con innerHTML;
  • movimientos sin transacción que permitían stock negativo;
  • roles que no restringían nada.
Solución
Parchearla no alcanzaba, así que la reescribí desde cero con React (Vite) y Supabase, con la seguridad dentro de la base de datos y no solo en la interfaz. Está desplegada en Vercel y se usa a diario en una escuela técnica.

Detalle técnico

  • RLS y permisos por columna: cada rol lee y modifica solo lo que le corresponde.
  • Stock auditable: no se edita a mano, cambia solo con movimientos registrados e inmutables.
  • Edge Function para administrar usuarios, sin exponer credenciales de servicio en el cliente.
  • Informe del laboratorio exportable a Excel.

81 tests de seguridad

  • Script SQL propio que corre en Supabase y simula cuatro perfiles: anónimo, profesor, estudiante e inactivo.
  • Verifica que un anónimo no acceda a nada y que cada rol tenga solo sus permisos, también por columna.
  • Que el stock cambie solo por movimientos, nunca quede negativo y que los movimientos sean inmutables.
  • Que nadie firme por otro ni cargue fechas pasadas, que siempre quede un profesor activo y que las vistas respeten RLS.
